# ぼぶる（Trade OS）

トレードの環境認識・シナリオ・記録・分析・ルールブックを1つにまとめた、単一 HTML の Web アプリ。
依存ライブラリなし・ビルド不要。`index.html` をブラウザで開くだけで動きます（PC とスマホで表示が変わります）。
公開版：https://hoshi2.github.io/bobru/

## 画面（2026-09-24 の作り直し後）

- **今日** — 数字タイル（口座残高・本日の損益・本日のR・勝率30日・連勝連敗・区切りまで）、環境認識（見方・各時間足の向き・前日高安・価格と EMA75/200 の位置・紫の状態・要約・ロング案／ショート案／見送り条件・重要指標）、保有中、口座の状況（目標・自分の日次停止・規約の損失枠のメーター）
- **シナリオ** — 価格・SL・TP・ロットを入れると右に予定損失／利益・リスク率・RR・推奨ロット・「この損切りで残り枠がどうなるか」をライブ計算。根拠（4H 環境・紫ライン・トリガー・EMA・クロス時の水色・紫の広がり）を3秒で押して記録
- **記録** — 保有中／下書き／決済済み／取消。PC は表（行を押すと詳細）、スマホはカード。決済登録では理由・逸脱・感情・学びを残す
- **分析** — 期間と「この口座／全体」で切替。統計タイル、累積損益・累積R・残高推移の線グラフ、月曜始まり・週の枠つきカレンダー、分類別の集計表（パターン・4H・紫ライン・EMA・クロス時の水色・紫の広がり・トリガー・決済理由・保有時間・逸脱…）
- **設定** — 口座（複数。ルール・通貨・終了・削除。終了した口座は折りたたみに移る）、計算、内部ルール、為替レート、表示、端末間の同期（Firebase のクラウド同期＋手動コード、受信箱）、データ（バックアップ・復元・CSV・削除）

## 朝の環境認識（自動）

平日 7:30（日本時間）にクラウドの Claude Code（ルーチン）が動き、`tools/asa/` のスクリプトで値動き（COMEX 金先物 GC=F をスポットに合わせてずらしたもの）から各時間足の向き・EMA・節目・BOB EDGE v1.8 の値を計算し、TradingView から現在値・前日高安・今週高安・経済指標を取り、AI がシナリオ2本＋見送り条件を書いて `briefs/latest.json` を push します。
アプリは起動時と画面に戻ったときに `briefs/latest.json` を見に行き、今日の環境認識が空なら自動で入れ、手で書いてあれば「反映」ボタンを出します。手順書は `.claude/skills/asa/SKILL.md`（Claude Code で `/asa` または「朝」）。

- `briefs/` は公開ページから誰でも読めます。口座・残高・取引の記録は入れません
- AI の見方（`aiBias`）と自分の判断（`bias`・メモ）は別に保存されます

## 取引日と時刻

- 1日は口座の区切り（Fintokei は NY17時＝日本の朝6〜7時。設定の無い口座も同じ）から次の区切りまで。始まった日の日本時間の日付で呼ぶので、金曜26時の決済は「金曜」。今日の損益・日次損失・分析の期間・カレンダー・取引日数・環境認識の「今日」はこの取引日で数える。記録の日時そのものは日本時間の ISO のまま
- カレンダーは月〜金だけ。土日に付いた決済があれば表の下に件数を出す
- 環境認識は、その取引日のぶんが無ければ直前の（2日以内）を「昨日の」と札を付けて今日に出す。朝7:30の自動生成で切り替わる
- 日時の入力欄には「MT5 の時刻で入力」の切替がある（設定に記憶）。口座ごとの「MT5 のサーバー時刻」（自動＝夏 UTC+3／冬 UTC+2、または固定）で日本時間に直して保存し、横に「→ 日本時間 …」を出す

## 口座と通貨

口座は複数持てます（JPY／USD）。XAUUSD のような USD建て銘柄は、口座通貨が JPY なら USDJPY を自動取得（無料の公開レート、更新は1日1回）して換算します。レートはエントリー時の値を記録に焼き込みます。受信箱から入る記録は取り込み先の口座の通貨でレートを付け（「いまの口座」が別の通貨でも正しく付く）、レートがまだ無ければ「待ち」にして取れ次第入れます（待ちの間は R を出しません）。口座の通貨を変えると、その口座の記録の通貨表示も揃えます。詳しくは [docs/fx-rate.md](docs/fx-rate.md)。
終わった口座は理由（合格・失格・期限切れ）を選んで終了にすると、設定の「終了した口座」に移り、記録と分析には残ります。「削除」は口座とその記録・画像を消します（記録の無い口座は確認1回、あれば二段階確認。最後の1口座は消せません）。削除は同期で他の端末にも伝わります。

## データの扱い

- 記録はブラウザの `localStorage` にその端末だけで保存（サーバーへは送りません）。データ版は 3
- 端末間の同期は設定の「端末間の同期」。自分の Firebase（Firestore）の設定と合言葉（同期コード）を各端末に貼ると、`boburu/{同期コード}` の1件に記録を丸ごと置き、保存のたびに自動で送り、相手の変更は自動で届く（習慣・お金・ロイログと同じ方式）。記録ごとに `_m`（最後に変えた時刻）を持ち、記録単位で新しい方が勝つ。消した記録は `syncMetadata.deleted` の墓標で相手側でも消える。画像は端末内のみ。最初の口座は id が決め打ち（`acc_default`）で、クラウドに別の口座があって最初の口座に取引も下書きも無ければ、つないだときに外す（端末を足しても空の同名口座が増えない、#31）。手動の同期コード（BOB1. 丸ごと上書き）も残してある。全データ削除・JSON 復元・手動の同期コードの取り込みは「この端末だけ」の置き換えで墓標を作らず、同期コードを貼り直した最初の接続ではこの端末の墓標を捨ててから合わせる。安全弁として、墓標で 10 件以上がまとめて消える合わせ込み（口座の削除で一緒に消える取引は数えない）は、合わせず・送らず同期を一時停止する（2026-10-21 の事故の再発防止、#33）
- JSON バックアップ／復元、CSV 出力あり
- 手で読み込む取引履歴（MT5 レポート／cTrader CSV）と「版番号」は 2026-10-17 に外した。取引は下の受信箱から入る前提（Dell が常時動いている。cTrader は使わない）
- **受信箱（自動取り込み）**: Dell の MT5 から集めた決済済み取引（`hoshi2/bob-edge` の `tools/mt5_history/push_inbox.py`）が、同期と同じ Firestore の別の1件 `boburu/{同期コード}__inbox` に届く。クラウド同期がオンなら、起動時と画面に戻ったとき（5分に1回まで）にそれを読み、まだ入っていない取引だけを（近い保有中の計画があれば紐付け、無ければ計画なしの記録として）「記録」に入れ、取り込んだ印（`consumed`）を受信箱に書き戻す。口座は記憶した口座番号 → 口座名で決め、無ければ**口座を自動で作る**（同じ名前でも口座番号が違えば「Funded7 (口座番号)」として別口座。種別・初期残高・ルールは同じ名前の直近の口座から引き継ぎ、無ければひな形。初期残高が分からないときは 0 なので 設定 → 口座 で直す）。設定 → 端末間の同期 の「受信箱の自動取り込み」で止められる。記録の本体 `boburu/{同期コード}` には受信箱側から触らない
- **建玉中（保有中に自動で出す）**: 受信箱の `open`（Dell が 10 分ごとに送る建玉中のスナップショット、bob-edge #23）も同じときに読み、まだ記録の無いポジションを「保有中」に入れる。手で先に書いた近い計画（同じ銘柄・方向・近い価格と時刻）があればそれに紐付け、無ければ「計画なし」で作る（id は `mt5o_<口座番号>_<ポジション番号>` の決め打ちなので、PC とスマホが同時に開いても1件にまとまる。消した記録は作り直さない）。記録の SL は R の計算に使うので最初の値のまま（空なら MT5 の値で埋める）、MT5 で SL / TP を動かすとカードに「今の SL …・今のリスク …」の行が出る（TP は札）。決済が `items` に届くと、同じポジション番号の記録が優先で決済済みになる（手で決済登録していても二重にならない）
- **SL / TP の動き**: Dell の見張り（bob-edge `watch_sltp.py`、30 秒ごと、#29）が建玉中の SL / TP を覚えていて、決済の1件に `slFirst / tpFirst / slLast / tpLast / sltpMoves` が付いて届く。途中で手で決済しても SL / TP が残る（記録の SL・TP が空なら最初の値で埋める。計画に紐付いたときは計画の値を残す）。R は今までどおり記録の SL（＝最初の SL）で計算。最初 → 最後の SL の動きで札「SL を詰めた／建値へ／利益側へ／広げた／外した」、TP が変わっていれば「TP を動かした」。分析に「SL の動かし方」の表、逸脱の中身に「SLを広げた・外した」。「外した」は一度は SL が入っていたと分かるときだけ
- **手で SL を動かしたとき（#37）**: 保有中の編集に「最初の SL（R の元・入力ミスの修正だけ）」と「今の SL（動かしたら書く）」の 2 欄。今の SL を書いて保存すると、記録の SL はそのまま、`slLast` と `sltpMoves`（`by:"manual"`）に残り、上と同じ札・分析に乗る。カードには「今の SL 4195 ・ 今のリスク -500 ・ RR 1:6.00」の行（建値以上なら「建値・リスク 0」、外していれば「なし」）。実現 R は今までどおり最初の SL で計算。MT5 連携の記録は Dell の値が正なので今の SL 欄は入力不可
