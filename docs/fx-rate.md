# 口座通貨への換算（USDJPY 自動取得）

## なぜ要るか

XAUUSD の損益は **USD** で出る（`価格差 × ロット × 契約サイズ`）。
口座が **JPY** だと、USD の損失額を JPY の残高と比べることになり、

- 予定リスク率が 0.00% のまま
- 推奨ロットが桁違い

になる。これを直すため、損益（建値通貨）→ 口座通貨 の掛け率を通す。

```
予定損失 = 価格差 × ロット × 契約サイズ × レート
推奨ロット = 許容損失額 ÷ (SL幅 × 契約サイズ × レート)
```

## 取得先（`fxRateProvider`）

`marketDataProvider` と同じ作りにしてある。取得先を `register` で足せて、
失敗・タイムアウトは層の中で握り、**取れなかった値は `null`**（推測しない）。
将来この2つは1つの取得層にまとめられる。

```js
fxRateProvider.register(name, {
  label, note,
  fetch: function(req){ return Promise<{base, rates:{JPY:156.1,…}, at}>; }
});
```

同梱の取得先（`FX_SOURCES` の順に試す）:

| name | 取得先 | 備考 |
|---|---|---|
| `erapi` | `open.er-api.com/v6/latest/USD` | 無料・キー不要・CORS 許可 |
| `currencyapi` | jsDelivr の `@fawazahmed0/currency-api` | 同上。1つ目が落ちたときの控え |

**どちらも1日1回更新**。日中のドル円の動きは反映されない。
リスク率の計算にはこれで十分（ドル円が1%動いてもリスク率は 1.00% → 1.01% 程度）だが、
「リアルタイムのレート」ではない点は画面にも書いてある。
キーの要る業者を使いたくなったら、`fetch` を1つ書いて `FX_SOURCES` に足す。

## 取得のタイミング

- 起動時と画面を描くたびに `ensureFxRate()` を呼ぶ（**期限切れのときだけ**動く）
- 画面に戻ったとき（`visibilitychange`）
- 設定の「いま取得する」
- キャッシュは **10分**（`FX_TTL_MS`）
- 口座通貨が USD なら通信しない

## 保存する形（`DB.settings.fx`）

```js
{
  auto:true,      // 自動取得する
  manual:null,    // 手動レート（自動が取れないときの控え）
  quote:"JPY",    // 取得値がどの通貨向けか（口座通貨を変えたら捨てる）
  rate:156.18,    // 直近で取得できた USD→口座通貨
  at:"…",         // ★ こちらが取りに行った時刻。キャッシュ期限はこれで見る
  rateAt:"…",     // 提供元がそのレートを出した時刻（日次なので古い）
  source:"…"
}
```

`at` と `rateAt` を分けているのが要点。
提供元の更新時刻で期限を見ると、1日1回しか動かないレートが常に期限切れ扱いになり、
描画のたびに取りに行ってしまう。

## 使う側

```js
quoteCurrencyOf("XAUUSD")  // → "USD"（末尾3文字が通貨コードならそれ）
fxRateFor("XAUUSD")        // → 156.18 / 1（換算不要）/ null（取れない）
fxRateOrOne("XAUUSD")      // → 計算に使う値。取れないときは 1
```

優先順位は **取得値 → 手動レート → なし**。
取れないときは 1 で計算し、画面に「1 で計算しています」と断りを出す（黙って間違えない）。

## 記録には焼き込む

`balanceAtEntry` と同じ考え方で、トレード記録に `fxRate` と `acctCurrency` を残す。
あとでレートが動いても、過去のリスク率と R は揺れない。

**レートを持たない過去の記録は 1 のまま**扱う。
そうしないと、これまでの記録の予定損失が突然 150倍になってしまう。
Phase 1 より前に入れた保有中トレードの数字を直したい場合は、入れ直しが要る。

## 決済登録

- 決済価格からの候補も口座通貨で出す（記録に焼いたレートを掛ける）
- 実現損益は **入力欄が絶対値・符号は「− 損失 / ＋ 利益」で選ぶ**。
  iOS の数字キーパッドにはマイナスが無く、損失を手で打てなかったため
- 決済価格を入れると符号が自動で合う。自分で選んだあとはその選択を優先する
- 取り違えよけに「登録される実現損益 −168,696 JPY」を保存ボタンの手前に出す

## どの通貨建てか

`tradeCurrency(t)` が答える。

| 記録 | 判定 |
|---|---|
| `acctCurrency` を持つ | その通貨 |
| `fxRate` を持つ | いまの口座通貨 |
| どちらも無い（Phase 1 より前） | 建値通貨（＝換算していない） |

口座通貨と違う建ての記録には、トレードカードに `USD建て` の印を出す。
新旧の記録が混ざっても数字を取り違えないため。

- 計画 — 残高の下に `USDJPY 156.18 ・最終取得 05:07 ・提供元の更新 00:02`
- 設定 — 口座通貨のプルダウン、自動取得の切り替え、手動レート、いま取得するボタン

## 確認していること

`node tests/run.mjs` のグループ11・12。

- USD口座は換算しない（従来の数字のまま）
- JPY口座はレートを掛けて、リスク率・推奨ロットが意味のある値になる
- 10分はキャッシュを使い、手動更新では取り直す
- 取得に失敗しても直近の成功値を捨てない／手動レートに落ちる
- 取れないときは 1 で計算し、そのことを画面に出す
- 記録に焼いたレートを使う／持たない過去の記録は 1 のまま
- 実 API の応答を写した固定データで、両取得先の解釈と切り替えを確認

## 未対応

- USD建て以外の銘柄の換算（例：EURJPY を USD 口座で）。1 で計算し、画面に断りを出す
- 日中のレート変動（取得先が日次更新のため）
