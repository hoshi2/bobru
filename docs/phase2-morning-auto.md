# Phase 2 — 「朝やろ」の一言で、前日の取引同期＋環境認識＋保存まで

> ゴール：iPhone で **「朝やろ」** だけ。
> Mac が OFF でも、スリープでも、MT5 を開いていなくても、
> **前日のトレード同期済み ＋ 今日の Morning Brief 作成済み ＋ ぼぶる保存済み** になる。

---

## 1. 現状（着手前）に何があったか

| | 中身 | 使えるか |
|---|---|---|
| ぼぶる本体 | 単一 `index.html`。依存ライブラリなし・ビルドなし・GitHub Pages 配信 | そのまま使う |
| 保存 | `localStorage` の `boburu_v1` だけ。**サーバも Firebase も無い** | 端末内に閉じている（後述） |
| 端末間の移動 | `BOB1.` + base64 の同期コードを手でコピペ。**丸ごと上書き** | 自動同期は無い |
| Morning Brief | 1日1件・`date` がキー。方向 / EMA / 高安 / セッション高安 / 指標 / シナリオ | 器はできていた |
| Brief ↔ トレード | `trade.briefId`、無ければ日付＋銘柄で解決（`briefOfTrade`） | 分析の土台はできていた |
| 市場データ | `marketDataProvider` という差し替え口だけ。中身は **未接続とデモの2つ** | 実データは繋がっていなかった |
| 為替 | `fxRateProvider` で実 API を2つ（キー不要・CORS 許可・1日1回更新） | 動いている。作りを踏襲した |
| MT5 | **接点なし** | 新規 |
| 回帰テスト | `tests/run.mjs`（Playwright）127件 | 足して使う |

**要点は「サーバが1つも無い」こと。** Firebase も無い。
`localStorage` は端末ごとに独立していて、iPhone から押した処理の結果を Mac が知る手段も、その逆も無い。
朝の自動化には、どうしても **常時動く場所** が1つ要る。

## 2. 何を足したか（この段階で入ったもの）

### 2-1. MT5 取引同期（`tradeSyncProvider`）

`marketDataProvider` / `fxRateProvider` と同じ形の差し替え口。同梱は3つ。

| name | 中身 |
|---|---|
| `none` | 未接続（既定）。何も取り込まない |
| `paste` | エージェントの JSON を貼り付ける。**VPS が無くても取り込める** |
| `relay` | VPS のエージェントが書き込んだ中継から取りに行く |

取り込みの決まり。

- **一意キーは deal ticket。** 同じ約定は二度入らない。何度実行しても結果が同じ（冪等）
- **建玉の一意キーは position ID。** 追加決済が来ても新しい記録は作らず、同じ記録が閉じる
- **MT5 から取れる事実だけ**を書く。エントリー根拠・感情・相場観・パターン・ルール遵守度は空のまま
- 入出金・手数料の行（`DEAL_TYPE_BALANCE` など）からはトレード記録を作らない
- **一部決済のうちは決済扱いにしない。** 含み益を実現損益にしない
- ドテン（1約定で建て替え）は正確に割れないので、**約定は保存するが記録は作らない**（件数を報告する）
- 手で直した値は次の同期で潰さない（3方向マージ）。食い違いは黙って消さずに報告する
- 手入力の記録と同じトレードらしきものは、**自動では混ぜず**「重複の可能性」として報告する

取り込む項目（MT5 から実際に取れるものだけ）:
symbol / buy・sell / エントリー時刻・価格 / 決済時刻・価格 / lot / profit / commission / swap /
order ticket / deal ticket / position ID / SL / TP / 契約サイズ / 口座番号・サーバ・口座通貨。

**SL/TP には注意がある。** 約定（deal）は SL/TP を持たない。

- 決済済み … 発注時の値（注文から引く）。途中で動かした値は履歴に残らない
- 保有中 … 建玉スナップショットの「いまの値」

ぼぶるは**スナップショットが取れた回だけ SL/TP を更新する**ので、
取れない回に発注時の値へ巻き戻ることはない。

`balanceAtEntry`（エントリー時の口座残高）は MT5 が約定に持たないので **空のまま**。
リスク率は出ないが、SL があれば予定損失は出るので **R は出る**。

### 2-2. 朝分析に実データの口（`marketDataProvider` の `relay`）

中継は**素の足（OHLC）を返すだけ**にして、指標の計算はぼぶる側に置いた。
データ業者を替えても、中継の関数を1つ書き換えるだけで画面は触らずに済む。

ぼぶる側で計算するもの:

| 項目 | 出し方 |
|---|---|
| 現在価格 | いちばん細かい足の終値 |
| EMA 10 / 75 / 200 | 最初の period 本の単純平均を種にした EMA |
| ATR 14 | Wilder |
| 日足 / 4H / 1H / 15M の方向 | 終値 > EMA75 > EMA200 → 上昇、逆 → 下降、それ以外 → レンジ |
| 前日高安 | その日より前で最後の日足（休場をまたいでも直前の営業日） |
| 週足高安 | ISO週（月曜はじまり）でその日を含む週の日足 |
| 直近高安 | 1時間足の直近24本 |
| セッション高安 | アプリが渡した窓（`Asia/Tokyo` / `Europe/London` / `America/New_York`。夏時間は自動追従） |
| USDJPY / DXY / 米10年債 | 中継の `quotes` から |

**本数が足りない足では値を出さない。** EMA200 が出せなければ方向は「データなし」のまま。
**シナリオ・今日の見方・要約は作らない**（相場観なので、AI に渡すのは Phase 4）。

### 2-3. 「朝やろ」

`runMorningRoutine()` が3段を順に回す。

```
1. 前日の取引を同期    tradeSyncProvider → DB.deals → DB.trades（冪等）
2. 市場データを取得    marketDataProvider → 作業コピーへ反映
3. 環境認識を保存      DB.briefs へ date をキーに upsert
```

- 各段の結果が画面に残る（○ / ! / × / − と一言）
- **デモのサンプル値は保存しない。** 作り物を記録に残さない
- **入る値が何も無いときは空の環境認識を作らない**
- 取得先が未接続の段は「飛ばした」と出る。黙って成功したふりをしない

iPhone からの呼び出しは URL だけ。

```
https://hoshi2.github.io/bobru/#morning
```

`#morning` で開くと自動で走り、ハッシュはすぐ消えるので再読込で二重には走らない。
ショートカットに「このURLを開く」を1つ置き、名前を「朝やろ」にすれば
**「ボブ、朝やろ」で Siri から呼べる**。

### 2-4. 環境認識とトレードの突き合わせ

成長タブに3つ足した。将来の分析ではなく、**いま動く形**で入っている。

- 朝の見方との関係 — 朝と同じ方向 / 朝と逆の方向 / 様子見の日に取った / 環境認識なし
- 朝の4時間足との関係 — 沿った / 逆らった / レンジの日
- 記録の出どころ — MT5 から同期 / 手入力

紐付けは `briefOfTrade()`（`briefId` 優先、無ければ日付＋銘柄）。既存データを書き換えずに載る。

## 3. データ構造（すべて加算・後方互換）

```js
DB.deals = [ {                    // ★新規。MT5 の事実そのまま
  ticket, order, positionId,      // 一意キーは ticket（文字列で持つ）
  time, type:"buy"|"sell"|"balance"|…, entry:"in"|"out"|"inout"|"outby",
  symbol, volume, price, profit, commission, swap, fee,
  sl, tp, contractSize, comment, magic, reason, account, currency
} ]

trade = {
  …従来どおり…,
  source:"mt5",                   // ★手入力と混ざらないよう印を付ける
  mt5:{ positionId, account, currency, entryDeal, exitDeals[], dealTickets[],
        closedVolume, exact, syncedAt,
        facts:{…} }               // 前回この記録に書いた MT5 の値。3方向マージに使う
}

brief = {
  …従来どおり…,
  atr:{ tf, value },                                              // ★
  context:{ usdjpy:{last,chg}, dxy:{last,chg}, us10y:{last,chg} }  // ★
}

settings = {
  …従来どおり…,
  marketRelay:{ endpoint, token },                                // ★朝分析の中継
  mt5:{ provider, endpoint, token, autoImport, lastSync, lastCount } // ★取引同期
}
```

端末に残す約定は **3000件を上限**にして、古いものから落とす。
同期コードもバックアップも丸ごと1本なので、際限なく伸ばさない。
落とすのは約定だけで、そこから作ったトレード記録は残る（落とした件数は取り込み結果に出る）。

`migrate()` は**ホワイトリスト方式**（知らないキーを捨てる）なので、
`db.deals = Array.isArray(p.deals)?p.deals:[]` の1行を足してある。これが無いと
リロード・復元・同期のたびに約定が消える。

`mergeSettings()` も `mt5` / `marketRelay` を**深いマージ**の対象に入れた。
浅いままだと、版を上げて増やしたキーが古い保存データで欠けたままになる。

CSV は**末尾に**追加（既存の列順は変えていない）:
`source` / `mt5PositionId` / `mt5EntryDeal` / `mt5ExitDeals` / `mt5Account`。

### 将来の分析に効く設計

「朝の方向性と同方向/逆方向の成績」「4Hに沿った/逆らった勝率」を出すのに要るのは

```
trade.briefId → brief.bias / brief.trend.h4
trade.dir     / trade.realizedPL / plannedLoss（R）
```

の3つだけで、**すでに全部ある**。`briefAgree(t)` / `briefTfAgree(t,tf)` がその判定。
時間帯別・曜日別は `createdAt` から、MT5由来かどうかは `source` から出せる。
新しい切り口が要るときは `classTable()` に行を足すだけで済む。

## 4. MT5 連携をどう実装するのが一番安全で現実的か

検討した案。

| 案 | 中身 | 判断 |
|---|---|---|
| ブラウザから MT5 を直接叩く | — | **不可能**。MT5 に Web API は無い |
| Fintokei / ブローカーの REST API | — | **無い** |
| MQL5 の EA から `WebRequest` で送る | 端末の中で動くので資格情報を持たない | 有力。ただし MQL5 を書いて保守する必要があり、チャートに貼り付けて動かす前提 |
| **Python（MetaTrader5）で端末につなぐ** | すでにログイン済みの端末に `initialize()` するだけ | **採用**。同じく資格情報を持たずに済み、書きやすく直しやすい |
| 投資家パスワードでログインする | 無人再ログインができる | 予備。読み取り専用なので発注はできない |

採用したのは4つ目。決め手は

- `mt5.initialize()` に**口座番号もパスワードも渡さない**。ログイン済みの端末につなぐだけ。
  → **スクリプトも設定ファイルもパスワードを持たない**
- `history_deals_get` / `history_orders_get` / `positions_get` / `account_info` /
  `symbol_info` で、要求されていた項目がほぼ全部取れる
- 失敗しても次の回で取り直すだけでよい（毎回まるごと送り、受け側が deal ticket で重複を落とす）

無人での再ログインがどうしても要るときだけ `MT5_LOGIN` / `MT5_SERVER` / `MT5_PASSWORD` を使うが、
**必ず投資家パスワード（読み取り専用）**にする。鍵が漏れても他人に発注はできない。

### 同期のタイミング

朝にまとめてではなく、**5分ごと**にした（タスクスケジューラ or `--interval 300`）。

- 決済のたびに送る仕組み（MT5 のイベント）は EA でしか取れず、Python 側からは張れない
- 5分なら「決済後に近いタイミング」の要件はほぼ満たせる
- 冪等なので、多く回しても記録は増えない。回数を上げるのは設定値1つ

## 5. VPS が必要なら、どの構成が良いか

MetaTrader5 の Python パッケージは **Windows 専用**なので Windows が要る。

| 案 | 費用の目安 | 判断 |
|---|---|---|
| **A. 業者・プロップ提供の VPS** | 条件つきで無料 | **まずここを確認する**。回線が取引サーバに近い |
| **B. Windows VPS（Vultr / Contabo / ForexVPS 等・2GB〜）** | 月10〜20ドル | **推奨**。以下はこれ前提 |
| C. 自宅の常時起動 Windows（ミニPC） | 電気代のみ | 回線と停電の面倒を自分で見る |
| D. Linux + Wine | 安い | 端末の更新で止まる。おすすめしない |

中継は **Cloudflare Workers + KV**（無料枠で足りる）にした。理由は

- VPS を外向きに公開しなくて済む（VPS は送るだけ、受けない）
- CORS と TLS が最初から片付く。GitHub Pages から直接叩ける
- 秘密を `wrangler secret` に置ける。入れ直せばその場で無効にできる

構成:

```
[Windows VPS]                     [Cloudflare Workers + KV]      [iPhone / PC]
 MT5端末（ログイン済み）
   └ mt5_agent.py  ──POST(HMAC署名)──▶ /api/deals ──GET(Bearer)──▶ ぼぶる 取引同期
                                       /api/ohlc  ──GET(Bearer)──▶ ぼぶる 朝分析
                                          ▲
                                  市場データ業者（APIキーはここだけ）
```

## 6. MT5 ログイン情報をどう扱うか

| 秘密 | 置く場所 | 置かない場所 |
|---|---|---|
| MT5 の取引パスワード | **どこにも置かない**（端末に手でログイン済みにしておく） | VPS の設定・中継・ぼぶる・Git |
| MT5 の投資家パスワード | 無人再ログインが要るときだけ VPS の環境変数 | 中継・ぼぶる・Git |
| エージェント↔中継の署名鍵 | VPS の環境変数 と 中継の secret | ぼぶる・Git |
| ぼぶるの読み取りトークン | 中継の secret と 端末の設定欄 | Git |
| 市場データ業者の APIキー | 中継の secret | ぼぶる・VPS・Git |

守り方。

- `POST /api/deals` は **HMAC-SHA256 署名 ＋ 5分の時刻窓**。署名は「時刻 + 本文」に掛けるので、
  盗んだ本文の使い回しが効かない
- `GET` は **`Authorization: Bearer`**。トークンを URL に載せないので、
  ログ・履歴・リファラに残らない
- ぼぶるが持つのは**読み取り専用トークンだけ**。取引はできず、履歴が読めるだけ
- 端末を無くしたら `wrangler secret put READ_TOKEN` で入れ直せば、その場で無効になる
- 取得URLは **https:// しか受け付けない**（`localhost` を除く）
- 中継の `ALLOW_ORIGIN` はぼぶるの URL 1つだけにする

**この設計では、MT5 の資格情報は VPS から一歩も出ない。**
中継にもぼぶるにも渡らないし、渡す口が無い。

## 7. まだ無いもの（次の段階）

| | 中身 |
|---|---|
| **Phase 3 — 端末間の自動同期** | いまも保存先は `localStorage`。iPhone で作った Brief は、同期コードを貼るまで PC に来ない。中継に `/api/brief` を足して、date をキーに双方向で寄せる。※取引同期と朝分析は中継経由なので、**朝の結果自体は iPhone だけで完結している** |
| **Phase 4 — シナリオと要約を AI に書かせる** | いまは取れた事実を並べるところまで。基本シナリオ / 逆シナリオ / 今日の見方 / 要約は空のまま。取得済みの snapshot を Claude API に渡して文章にする。キーはブラウザに置けないので中継が要る。「取れない項目は推測で埋めない」「売買執行はしない」をプロンプト側にも書く |
| **Phase 5 — 当日の重要経済指標の自動取得** | いまは手入力。経済指標カレンダーの取得先を中継に足す |
| Phase 6 — 決済直後の同期 | 5分ごとを、MQL5 の EA から決済イベントで蹴る形にする |

### 決めておきたいこと

- セッション定義（東京 09–15 / ロンドン 08–16:30 / NY 08–17）が実運用と合っているか
- 日付の境界。`today()` はローカル日付なので、NY 深夜のトレードは翌日の Brief に紐付く
- MT5 の口座通貨とぼぶるの設定が食い違うと数字がずれる（取り込み時に警告は出る）
- 過去のトレードを手入力で入れてある期間は、MT5 同期と重複しうる（自動では混ぜず報告する）
